# Ollama Translator — план: краткое содержание страницы

Кнопка «Краткое содержание» в popup или пункт в контекстном меню, и у правого края страницы
открывается панель, где по мере генерации появляется краткое содержание страницы на языке
перевода. Переключатель «Коротко / Подробно» задаёт длину. Пункт меню на выделенном тексте
«Кратко о выделенном» делает то же для выделенного фрагмента.

Работаем этап за этапом. После каждого этапа — короткий отчёт и чек-лист ручной проверки.

## Решения (поменять до начала этапа)

| Вопрос | Решение |
|---|---|
| Где показываем | Панель у правого верхнего края страницы, в главном фрейме, в закрытом shadow DOM, как всплывашка выделенного. Закрывается кнопкой × или Esc, если фокус в панели. Клик мимо панель не закрывает: её читают вместе со страницей |
| Длина | Переключатель «Коротко / Подробно». Коротко — суть в 1–2 предложениях и 3–5 пунктов. Подробно — обзор в 2–3 предложениях, все важные факты пунктами, по частям текста с подзаголовками. Последний выбор запоминается (`summaryLength` в `storage.local`). Переключение — новый запрос; то, что уже готово, пока панель открыта, второй раз не запрашиваем |
| Язык | `targetLang` из настроек. Исходный текст может быть на любом языке |
| Как запустить | Кнопка «Краткое содержание» в popup; пункт меню на странице «Краткое содержание страницы»; пункт меню на выделенном «Кратко о выделенном». Хоткея нет |
| Модель | Та, что выбрана в popup, с теми же temperature и num_ctx. num_ctx не меняем: если он другой, Ollama перезагружает модель |
| Очередь к Ollama | Как у перевода выделенного (`withPrioritySlot`): краткое содержание обгоняет перевод страниц, а тот ему уступает |
| Какой текст берём | Основной текст: самый большой `article`, если он заметно больше остальных, иначе `main` / `[role=main]`, иначе `body`. Без nav, aside, footer, форм, диалогов и скрытого. Только главный фрейм. Если страница уже переведена, берём то, что на ней сейчас (перевод) |
| Длинный текст | Делим на части под num_ctx. Из каждой части модель делает заметки, они одинаковые для обеих длин; из заметок — итог. Пока идут части, панель показывает «Читаю часть 2 из 5…». Заметки последних текстов хранятся в памяти service worker'а, поэтому смена длины на длинной странице — это только финальный запрос. Предел — 150 000 символов, дальше обрезаем и пишем об этом в панели |
| Вывод | Стримом. Ждём простой текст: строки на «- » — пункты, на «## » — подзаголовки, остальной Markdown (`**…**`) снимаем. Только `textContent` |
| «Стоп» | Обрывает запрос; панель пишет «Остановлено» и даёт «Повторить» |
| Кэш | Только в памяти. На диск ничего не пишем |
| Не делаем | Краткое содержание видео YouTube по субтитрам, текст из iframe, свои настройки на странице настроек |

## Устройство

Новый модуль `src/summary/`, независимый от `page/`, `selection/` и `dub/`. Подключается
строкой импорта в `src/background.js` и строками в `src/popup/popup.html` (кнопка и скрипт —
так же, как раздел озвучки в `options.html`). Манифест не меняется: права `contextMenus`,
`scripting` и `activeTab` уже есть.

```
src/summary/
  background.js   часть service worker'а: пункты меню, summarizeTab из popup, внедрение
                  панели, порт "summary"
  popup.js        кнопка «Краткое содержание» в popup
  extract.js      content script: основной текст страницы
  panel.js        content script: панель
  lib/
    prompt.js     промпты и тела запросов (ES-модуль)
    chunks.js     бюджет символов под num_ctx, обрезка и деление на части (ES-модуль)
    format.js     ответ модели → абзацы, пункты, подзаголовки (обычный скрипт для panel.js)
```

```
вкладка (главный фрейм)                              service worker
┌──────────────────────────────┐                    ┌──────────────────────────────┐
│ summary/panel.js             │   порт "summary"   │ summary/background.js        │
│  extract.js → текст страницы │ ── summarize ────▶ │  withPrioritySlot            │
│  переключатель длины,        │ ◀─ source, ─────── │  части → заметки → итог      │
│  стрим ответа, копирование   │    progress,       │  chatWithRetry + onContent   │
│                              │    partial, result │                              │
└──────────────────────────────┘                    └──────────────────────────────┘
```

Порт: один запрос на порт, как у всплывашки выделенного. Панель закрыли или сменили длину —
порт закрыт, запрос к Ollama отменён.

- Панель → сюда: `summarize { text, title, length }`, `ping`.
- Отсюда → панели: `source { used, total }` — сколько символов ушло модели;
  `progress { part, parts }` — читаем длинный текст по частям (этап 2); `partial { text }` —
  ответ по мере генерации; `result { text, cut }` — готово, `cut` — ответ упёрся в num_ctx;
  `error { code, message }`; `stopped`.

### Что меняется в общем коде

Только точки расширения, без кода модуля:

- `lib/ollama.js`: у `chat` необязательный `opts.onContent(content)`, который получает
  накопленный ответ после каждого куска стрима;
- `lib/translate.js`: `chatWithRetry` экспортируется и пробрасывает `onContent`. После повтора
  ответ начинается заново, и панель просто показывает новый текст;
- `lib/prompt.js`: экспортируется `baseRequest`, общая часть тела запроса;
- `src/shared/clipboard.js`: копирование в буфер из всплывашки выделенного выносим в общий
  скрипт (как `shadow-host.js`), им пользуются и всплывашка, и панель.

### Как удалить модуль

Папка `src/summary/`, строка импорта в `src/background.js`, кнопка, заметка и строка
`<script>` в `src/popup/popup.html`.

## Этап 1. Панель и краткое содержание страницы

### Что видит пользователь

- В popup под кнопками перевода — «Краткое содержание». Она активна, когда Ollama и модель в
  порядке. Нажатие закрывает popup и открывает панель на странице.
- В контекстном меню страницы — «Краткое содержание страницы». В Chrome оба пункта страницы
  теперь в подменю «Ollama Translator».
- Панель: «Читаю страницу…», потом текст появляется по мере генерации. Внизу — сколько
  символов страницы учтено. «Коротко / Подробно», «Копировать», «Повторить» после ошибки, ×.
- Пока длинные страницы не делятся на части, учитывается только начало, примерно на
  num_ctx: «Учтено начало страницы: 17 000 из 54 000 символов».
- «Стоп» в popup обрывает генерацию: «Остановлено», «Повторить».

### Файлы

Новые: `src/summary/{background,popup,extract,panel}.js`,
`src/summary/lib/{prompt,chunks,format}.js`, `src/shared/clipboard.js`.
Меняются: `src/background.js`, `src/popup/popup.html`, `src/lib/{ollama,translate,prompt}.js`,
`src/selection/{bubble,background}.js`.

## Этап 2. Длинные страницы

- `chunks.js`: деление текста на части по абзацам под бюджет num_ctx, примерно поровну.
- Заметки по частям (промпт заметок), затем итог из заметок нужной длины. Если заметки сами
  не влезают в контекст, сводим их ещё раз.
- `progress` → «Страница длинная — читаю по частям: 2 из 5…», «Свожу заметки по частям…»,
  «Пишу краткое содержание…»; `registerQueue` — оставшиеся части, чтобы «■ Стоп» в popup был
  виден между запросами.
- Кэш заметок последних трёх текстов в service worker'е, по мере готовности частей: «Подробно»
  после «Коротко» на длинной странице — один запрос, а прерванный запрос продолжается с
  прерванной части.
- Предел 150 000 символов, сверх него: «Учтено начало страницы: N% текста».

## Этап 3. Кратко о выделенном и документация

- Пункт меню на выделенном «Кратко о выделенном». Текст берём со страницы во фрейме
  выделения (с переносами строк), если туда нельзя — из меню. Панель — в главном фрейме,
  заголовок «Кратко о выделенном».
- Слишком короткий текст (меньше 200 символов): «Тут почти нечего сокращать», без запроса.
- README: раздел про краткое содержание. Проверка в Firefox. `PLAN.md` удаляем.
