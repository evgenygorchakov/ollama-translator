# Ollama Translator — план: озвучка YouTube-видео на русском

Функция как в Яндекс Браузере. В плеере YouTube есть кнопка «Озвучить». Нажимаешь, идёт
подготовка, потом видео идёт с русским голосом, а оригинал приглушён фоном.

Как устроено в двух словах: берём английские субтитры видео, режем их на фразы с таймкодами,
переводим через Ollama (та же модель, что для страниц), озвучиваем каждую фразу Silero и
проигрываем её в момент, когда в видео начинается соответствующая английская фраза.

Работаем этап за этапом. После каждого этапа — короткий отчёт и чек-лист ручной проверки.
Первые два этапа не требуют Silero: его ставим на этапе 3, когда он понадобится.

## Решения (поменять до начала этапа)

| Вопрос | Решение |
|---|---|
| Синтез речи | Silero `v5_5_ru` через ваш HTTP-сервер из `sup/optional/voice`: `POST /synthesize`, порт 5011. Ollama речь не синтезирует |
| Silero на Windows | Нативно: тот же `server.py` в venv через uv, автозапуск при входе в Windows. Копия сервера и инструкция — в `tools/silero/` |
| Silero на Linux | Как сейчас: systemd user-сервис из `sup/optional/voice` |
| Откуда текст | Английские субтитры YouTube: ручные, если есть, иначе автоматические. Если нет ни тех, ни других, кнопка пишет «Нет английских субтитров». Whisper не используем |
| Язык озвучки | Только русский: Silero умеет только его. Настройка `targetLang` на озвучку не влияет |
| Когда начинается голос | Когда готовы первые ~30 с от текущей позиции. Остальное готовим с опережением. Если подготовка отстала, видео встаёт на паузу, как при буферизации |
| Оригинальный звук | Приглушается до 15%, уровень задаётся в настройках |
| Если фраза длиннее своего места | Сначала темп Silero `fast` (×1,2) или `x-fast` (×1,5), потом небольшое ускорение воспроизведения. Вместе не больше ×1,5 (настройка) |
| Модель перевода | Та же, что выбрана в popup |
| Очередь к Ollama | Как у перевода выделенного: озвучка обгоняет перевод страниц |
| Где кнопка | Поверх плеера, в левом верхнем углу. Видна вместе с панелью управления YouTube, а во время подготовки и при ошибке — всегда |
| Русские субтитры | Нужны на этапе 2 для проверки перевода. Дальше это настройка, по умолчанию выключена |
| Кэш | Только в памяти вкладки, пока открыто видео. На диск ничего не пишем |
| Не поддерживаем | Shorts, плееры, встроенные в другие сайты, прямые трансляции, m.youtube.com |

## Устройство

Новый модуль `src/dub/`, как `page/` и `selection/`: он независим от них, общее у всех только
`src/lib/`. Всё, что нужно только озвучке, лежит в `src/dub/`, включая её чистую логику
(`src/dub/lib/`), настройки и промпты. Общий код озвучка только использует, не меняя его:
точки расширения для неё уже есть (см. «Что модуль берёт из общего кода»).

```
src/dub/
  background.js       часть service worker'а: порт "dub", сессии (импорт из src/background.js)
  page-captions.js    функция для executeScript в MAIN world: дорожки субтитров → json3
  content.js          content script: кнопка, состояние, субтитры
  player.js           content script: звук фраз и синхронизация с <video> (этап 4)
  options.js          раздел «Озвучка видео» на странице настроек (этап 3)
  lib/                чистая логика, ES-модули
    captions.js       json3 → слова → фразы
    queue.js          планировщик: что переводить и озвучивать дальше
    prompt.js         DUB_PROMPTS — промпты перевода для озвучки
    settings.js       настройки озвучки: ключи dub*, дефолты, диапазоны
    tts.js            клиент Silero
    wav.js            длительность wav
    fit.js            подгонка длины фразы (этап 4)
```

```
вкладка YouTube                                       service worker
┌──────────────────────────────┐                     ┌──────────────────────────────┐
│ dub/content.js (isolated)    │    порт "dub"       │ dub/background.js            │
│  кнопка, состояние,          │ ──── start, ──────▶ │  сессия на порт:             │
│  синхронизация с <video>,    │      position       │   субтитры → фразы           │
│  проигрывание, приглушение   │ ◀─── phrases, ───── │   перевод (lib/translate,    │
│                              │      translated,    │     слоты, как выделенное)   │
│                              │      audio (base64) │   синтез (dub/lib/tts)       │
└──────────────────────────────┘                     └──────────────────────────────┘
        ▲ executeScript(world: "MAIN"): плеер → список дорожек субтитров → json3
```

### Что модуль берёт из общего кода

Всё это уже есть, менять для озвучки не нужно:

- `lib/priority.js`: `withPrioritySlot({ signal, prompts }, fn)`. Ждёт слот раньше очереди
  страниц, при этом перевод страниц уступает. После ожидания перечитывает настройки, вызывает
  `markModelUsed`, создаёт контекст перевода. Так же работает перевод выделенного;
- `lib/translate.js`: `translateTexts(texts, ctx)`, `translateOne`. Промпты — в
  `ctx.prompts = { batch, single, singleViaBatch }`. Озвучка передаёт свои `DUB_PROMPTS`
  через `withPrioritySlot` (или третьим аргументом в `createContext`), настройки
  `targetLang` и `systemPrompt` на неё не влияют;
- `lib/keepalive.js`: `keepAwake()` → функция «отпустить». Не даёт service worker'у уснуть,
  пока у сессии есть работа (слоты держат его сами только на время запроса к Ollama);
- `lib/stop.js`: `onStop(fn)`, `registerQueue(fn)` — «■ Стоп» и счётчик очереди в popup;
- `lib/settings.js`: `getSettings()` (модель, адрес Ollama), `clampNumbers`, `normalizeUrl` —
  для своих настроек в `dub/lib/settings.js`;
- `lib/host-permission.js`: `parseServerUrl`, `ensureHostPermission(url, builtinHosts)` — для
  адреса Silero на странице настроек;
- `shared/keepalive-port.js`: `connectPort` для порта `"dub"`;
- `lib/port.js`: `safePost`.

На YouTube в одном isolated world могут оказаться и скрипты озвучки, и перевод страницы (если
его включат). Поэтому озвучка занимает в `window.__ollamaTranslator` только ключ `dub` и не
отвечает на сообщения перевода страницы (`getState`, `toggle`, `pause`): у неё свой порт.

### Как удалить озвучку

1. Удалить папку `src/dub/` (и `tools/silero/`, если не нужен сервер).
2. `src/background.js`: убрать строку `import "./dub/background.js"`.
3. `manifest.json`: убрать блок `content_scripts` для YouTube и из `host_permissions` адреса
   `youtube.com` и Silero (`:5011`).
4. `src/options/options.html`: убрать раздел «Озвучка видео» и
   `<script type="module" src="../dub/options.js">`.
5. `CLAUDE.md`: убрать строки про Silero.

Ключи `dub*` в `chrome.storage.local` останутся, но никому не мешают: их сотрёт «Сбросить
настройки».

- **Субтитры** читаются в MAIN world страницы: только там доступен
  `#movie_player.getPlayerResponse()`. Service worker вызывает
  `chrome.scripting.executeScript({ world: "MAIN", func })` на вкладке, с которой пришёл
  порт. Функция отдаёт сырые события субтитров, а режет их уже service worker.
- **Звук** запрашивает только service worker. Content script не может ходить на
  `127.0.0.1:5011` (CORS и защита локальной сети в Chrome), а у service worker'а есть
  host_permissions. Сообщения Chrome сериализует в JSON, поэтому `ArrayBuffer` передаём
  строкой base64. Это ~1,3 МБ на 10 с речи (wav, 48 кГц, моно).
- **Проигрывает** content script: по `<audio>` на фразу, с `preservesPitch`, чтобы
  ускорение не меняло высоту голоса.
- **Чистая логика** живёт в `src/dub/lib/`: разбор субтитров на фразы, планировщик «что
  готовить дальше», подбор темпа, длительность wav, клиент Silero.

## Риски — их проверяем первыми на своём этапе

1. **Субтитры.** С 2025 года YouTube требует для `/api/timedtext` токен PO (proof of origin):
   без него сервер отвечает 200 с пустым телом. Плеер сам получает токен, когда включаются
   субтитры. Поэтому этап 1 начинается с проверки в вашем браузере, какой из трёх способов
   работает сейчас (см. этап 1). **Проверено на этапе 1: работает способ б** (токен из запроса
   плеера), только он и оставлен.
2. **Скорость перевода.** Узкое место — Ollama, а не Silero (RTF 0,02–0,03). Минута речи —
   это примерно 400–500 токенов ответа. При 30 ток/с минута видео готовится за ~15 с, при
   8 ток/с — почти в реальном времени, и видео будет вставать на «догрузку». `qwen3.8`
   (17 ГБ) не влезает в 12 ГБ VRAM, `gemma4` (6,6 ГБ) влезает. Скорость меряем на этапе 2.
   Если не хватит, добавим отдельную настройку «модель для озвучки».
3. **Silero не читает цифры и латиницу.** Промпт перевода для озвучки требует писать числа
   словами, а имена и названия — кириллицей. Проверяем на русских субтитрах этапа 2.
4. **Приглушение оригинала.** Если менять `video.volume`, YouTube запомнит громкость как
   пользовательскую. Поэтому приглушаем через Web Audio (`GainNode`). Проверяем на этапе 4
   в обоих браузерах. Запасной вариант — `video.volume` с восстановлением.
5. **`blob:` для `<audio>` на YouTube** (CSP, Firefox). Проверяем на этапе 4. Запасные
   варианты — `data:` URL или Web Audio.
6. **Silero из WSL на порту 5011.** WSL пробрасывает порты Linux на Windows: если в WSL
   работает systemd-Silero из `sup`, порт 5011 на Windows держит `wslrelay`. **Проверено на
   этапе 3:** нативный сервер, запущенный вторым, садится на тот же порт без ошибки (Flask
   ставит `SO_REUSEADDR`), но запросы уходят в WSL. Рабочая копия в WSL
   (`~/.local/share/silero/server.py`) старее копии в `sup`: в ней нет темпа, поле `rate`
   молча игнорируется. Расширению это видно по пустому `rates` в `/voices`, а страница
   настроек пишет «старая версия server.py». Лечится обновлением копии в WSL
   (`tools/silero/README.md`). На этапе 4, если `rates` пуст, длину подгоняем только
   `playbackRate`.

## Этап 1. Кнопка в плеере и субтитры

Ни Ollama, ни Silero на этом этапе не нужны.

### Что видит пользователь

- На странице видео (`/watch`) в левом верхнем углу плеера есть кнопка **«Озвучить»**.
  Она появляется и прячется вместе с панелью управления YouTube.
- Нажатие показывает «Загружаю субтитры…», потом, например, «Субтитры: 214 фраз
  (автоматические)». В консоли страницы видна таблица фраз (`console.table`) со столбцами
  начало, конец, текст. На этапе 2 эта отладка уйдёт.
- Если нет английских субтитров — «Нет английских субтитров». На трансляции кнопки нет.
- Переход на другое видео без перезагрузки страницы (YouTube — SPA) сбрасывает кнопку.

### Как устроено

- **manifest.json**:
  - `content_scripts` для `https://www.youtube.com/*`: `src/shared/keepalive-port.js`,
    `src/dub/content.js`, `run_at: document_idle`;
  - в `host_permissions` добавляем `https://www.youtube.com/*` (нужно для
    `executeScript` в MAIN world), а также `http://127.0.0.1:5011/*` и
    `http://localhost:5011/*` для Silero, чтобы этап 3 не трогал манифест.
- **`src/dub/content.js`**:
  - кнопка — custom element с закрытым shadow DOM, как всплывашка в `selection/bubble.js`.
    Стили внутри shadow, текст только через `textContent`. На YouTube `innerHTML` к тому же
    запрещён Trusted Types;
  - видимость следует классу `ytp-autohide` у `#movie_player` (MutationObserver на атрибут
    `class`);
  - смена видео ловится по событию `yt-navigate-finish` на `document` и сверкой `v=` в URL:
    всё сбрасываем, кнопку ставим заново, если плеер пересоздан.
- **`src/dub/background.js`** (импорт из `src/background.js`, одна строка рядом с `page/` и
  `selection/`). На этом этапе это сообщение `dubCaptions`: `executeScript` в MAIN world →
  разбор → ответ со списком фраз. На этапе 2 оно станет частью порта.
- **`src/dub/page-captions.js`** — функция для `executeScript({ world: "MAIN", func })`,
  самодостаточная, без замыканий:
  1. `movie_player.getPlayerResponse()`. Проверяем, что `videoDetails.videoId` совпадает с
     URL (после SPA-перехода плеер обновляется не сразу — несколько повторов с паузой).
     Трансляцию узнаём по `videoDetails.isLive` и отказываемся.
  2. Дорожка: из `captions.playerCaptionsTracklistRenderer.captionTracks` с `languageCode`
     на `en`. Ручная важнее автоматической (`kind: "asr"`).
  3. Загрузка. Пробуем способы по очереди, а на этапе оставляем тот, что работает:
     - а) `fetch(baseUrl + "&fmt=json3")`. Если тело пустое, нужен токен PO;
     - б) включаем субтитры плеера на эту дорожку через API плеера (`setOption("captions",
       "track", …)`). Ждём его собственный запрос `/api/timedtext` в
       `performance.getEntriesByType("resource")`, берём из этого URL параметры
       `pot`/`potc`, ставим `fmt=json3` и загружаем. Потом возвращаем субтитрам прежнее
       состояние;
     - в) запасной вариант — innertube `get_transcript` (панель «Расшифровка видео»).
       Таймкоды там грубее: по строкам, а не по словам.
- **`src/dub/lib/captions.js`** (ES-модуль, работает в service worker):
  - `parseJson3(json)` — события json3 превращает в слова с абсолютным временем.
    У автосубтитров время пословное (`segs[].tOffsetMs`), у ручных — только начало и
    длительность реплики;
  - `toPhrases(words)` — фразы `{ id, start, end, text }`:
    - убираем неречевое: `[Music]`, `[Applause]`, `♪`, `(laughs)`;
    - `>>` (смена говорящего) — всегда граница фразы;
    - граница — по концу предложения (`.?!…`), если пунктуация есть, и по паузе ≥ 0,7 с;
    - длинную фразу (> 12 с или > 200 символов) режем по самой длинной паузе внутри.
      Обрывки короче 1 с подклеиваем к соседу;
    - `id` — номер фразы. Разбор детерминированный, поэтому повторный даёт те же id.

### Файлы

`manifest.json`, `src/background.js` (одна строка импорта), `src/dub/background.js`,
`src/dub/page-captions.js`, `src/dub/content.js`, `src/dub/lib/captions.js`.

### Чек-лист

1. Перезагрузить расширение и открыть английское видео с автосубтитрами (лекцию, интервью).
   Кнопка «Озвучить» видна при наведении на плеер и прячется вместе с панелью YouTube.
2. Нажать кнопку → «Субтитры: N фраз (автоматические)». В консоли страницы (F12) таблица
   фраз: предложения разумной длины, таймкоды растут, нет `[Music]`.
3. Видео с ручными английскими субтитрами → «(ручные)», текст с пунктуацией.
4. Русское видео без английских субтитров → «Нет английских субтитров».
5. Перейти на другое видео через рекомендации, без перезагрузки → кнопка сброшена. Нажать →
   первая фраза в таблице от нового видео.
6. Если субтитры YouTube (CC) были выключены, после нажатия они так и остаются выключенными.
7. Трансляция → кнопки нет.
8. Firefox: пункты 1, 2, 5. Если кнопки нет, проверить about:addons → Ollama Translator →
   Разрешения → доступ к youtube.com.
9. Chrome на Linux: пункты 1–2.

## Этап 2. Перевод фраз и русские субтитры

Silero ещё не нужен. Перевод проверяем по субтитрам поверх видео.

### Что видит пользователь

- Нажатие «Озвучить» ставит видео на паузу и показывает «Готовлю перевод… 40%». Это
  процент первых 30 с от текущей позиции. Когда они готовы, видео продолжается, если играло
  до нажатия. Внизу плеера — русские субтитры, синхронно с речью.
- Перевод идёт с опережением, примерно на 3 минуты вперёд. При перемотке сначала
  переводится новое место.
- Повторное нажатие («Озвучка ✓») выключает озвучку.
- Нажатие во время рекламы — «Озвучу после рекламы»: подготовка начнётся, когда она кончится.
- Ошибки — на кнопке с подсказкой: «⚠ Ollama не отвечает», «⚠ Выберите модель в popup».
  Нажатие — повтор.
- «■ Стоп» в popup (и `Alt+Shift+S`) останавливает подготовку. Кнопка становится
  «▶ Продолжить», видео, которое ждало перевода, продолжается.
- При ошибке и после «Стоп» рядом с кнопкой крестик ✕ — выключить озвучку.

### Как устроено

- **Порт `"dub"`** через `connectPort` из `keepalive-port.js`. Пока идёт подготовка, он
  шлёт ping.
  - content → service worker:
    - `start { videoId, time, phrases?, translations? }` — включение, «▶ Продолжить» после
      «Стоп», повтор после ошибки и переподключение. Фразы и переводы хранит вкладка и
      присылает их: после перезапуска service worker'а субтитры не загружаются, а готовое не
      переводится заново;
    - `position { time }` — после перемотки и раз в 5 с во время просмотра.

    Выключение и смена видео — вкладка закрывает порт, отдельных `stop`/`resume` нет.
  - service worker → content:
    - `phrases { list, kind }`;
    - `translated { ids, texts }` — фраза, которую модель так и не перевела, приходит
      пустой: её пропускаем и не переводим снова;
    - `error { code, message, detail }`;
    - `stopped`. Вкладкам YouTube без порта «Стоп» шлёт `dubStopped` через
      `tabs.sendMessage`: иначе при просмотре они подключились бы снова и запустили модель.
      Если вкладка за это время успела подключиться, на `dubStopped` она закрывает порт. Если
      «Стоп» застал порт до первого `start`, ответ на этот `start` — `stopped`.
  - Порт умер (service worker уснул, когда переводить было нечего): во время подготовки
    вкладка подключается сразу, при просмотре — со следующей позицией. После «Стоп» и ошибки
    позицию вкладка не шлёт.
- **`src/dub/background.js`**, сессия на порт:
  - на `start` загружает субтитры (этап 1), режет на фразы и отдаёт их вкладке;
  - цикл подготовки спрашивает у планировщика следующий батч и переводит его:
    `withPrioritySlot({ signal, prompts: DUB_PROMPTS }, (ctx) => translateTexts(texts, ctx))`,
    как перевод выделенного. Пользователь ждёт прямо сейчас, поэтому перевод страниц ему
    уступает. `markModelUsed` и перечитывание настроек после ожидания слота `withPrioritySlot`
    делает сам;
  - порт отключился → `AbortController` сессии, запросы к Ollama обрываются;
  - `onStop`: сессии на паузу, запросы оборвать, вкладкам — `stopped`.
    `registerQueue`: сколько фраз в окне ещё ждёт перевода;
  - service worker не должен уснуть, пока у сессии есть работа. Во время запроса к Ollama
    его держат слоты. Между запросами сессия держит его сама: `keepAwake()` из
    `lib/keepalive.js`, пока работа есть, и вызов возвращённой функции, когда её не стало.
- **`src/dub/lib/queue.js`** — планировщик, чистые функции. По фразам, их состоянию и
  позиции воспроизведения возвращает следующий батч перевода: подряд идущие непереведённые
  фразы от первой, чей `end` больше позиции, в окне `[позиция, позиция + 180 с]`, в пределах
  `batchMaxItems`/`batchMaxChars` из настроек. Подряд идущие фразы в одном батче — это
  контекст для модели: автосубтитры режутся посреди предложения. Батч, который начинается в
  первых 30 с, дальше них не идёт: их пользователь ждёт, а ответ на батч приходит целиком.
  Если вперёд переведено больше 120 с, батч ждёт, пока непереведённого в окне наберётся на
  полный: иначе при просмотре шли бы батчи из одной-двух фраз. После перемотки идущий батч
  обрывается, если он весь вне окна или перед ним есть непереведённое из первых 30 с.
- **Промпты** (`src/dub/lib/prompt.js`): `DUB_PROMPTS = { batch, single, singleViaBatch:
  false }` — формат `ctx.prompts` из `lib/translate.js`. Язык в промптах всегда русский.
  `batch` — для JSON-батча. Субтитры переводятся для озвучки синтезатором:
  - каждый элемент переводится отдельно, коротко, живой разговорной речью, без слов-паразитов,
    чтобы фраза уложилась примерно в то же время;
  - числа, даты, единицы, символы и сокращения пишутся словами в нужном падеже;
  - имена, бренды и термины пишутся кириллицей, как их произносят по-русски;
  - никакой латиницы, цифр, эмодзи и комментариев.

  `single` — для одиночного запроса без JSON (повтор элемента, который модель не перевела в
  батче), с теми же правилами. Встроенный промпт страниц сюда не годится: он велит сохранять
  латиницу и цифры.
- **`src/dub/content.js`**:
  - хранит `translations: Map<id, text>` для текущего видео;
  - субтитры — элемент в shadow DOM над нижней панелью плеера. Текущую фразу ищет
    бинарным поиском по `video.currentTime` на `timeupdate` и `seeked`;
  - видео на паузу ставим только при нажатии, а продолжаем, только если поставили сами: когда
    готовы первые 30 с, при ошибке и при «Стоп»;
  - во время рекламы (`ad-showing` у плеера) `<video>` играет рекламу и время у него её.
    Нажатие тогда ждёт первого `timeupdate` после рекламы, а позицию не шлём;
  - если порт умер (перезагрузка service worker'а), переподключаемся и шлём `start` с уже
    полученными переводами.
- `console.debug` с ток/с уже есть в `translate.js` — по нему меряем скорость.

### Файлы

`src/dub/background.js`, `src/dub/content.js`, `src/dub/lib/queue.js` (новый),
`src/dub/lib/prompt.js` (новый).

### Чек-лист

1. Ollama запущена, модель выбрана. Английское видео → «Озвучить» → «Готовлю перевод… N%» →
   видео продолжается с русскими субтитрами. Записать, сколько секунд заняла подготовка и
   какие ток/с в консоли service worker'а (`chrome://extensions` → «service worker»). Лучше
   для двух моделей: `gemma4` и `qwen3.8`.
2. Субтитры меняются вместе с речью. Числа словами, имена кириллицей, латиницы нет.
3. Посмотреть 5 минут подряд: субтитры не кончаются, подготовка идёт впереди.
4. Перемотать на 10 минут вперёд → через несколько секунд там тоже субтитры.
5. Во время подготовки «■ Стоп» в popup → GPU отпускает, `ollama ps` пуст, на кнопке

## Этап 4. Озвучка

### Что видит пользователь

- «Озвучить» → видео на паузе, «Готовлю озвучку… N%». Когда готовы первые ~30 с, видео
  продолжается с русским голосом, оригинал звучит тихо фоном.
- Каждая русская фраза начинается вместе со своей английской. Длинные фразы звучат быстрее,
  но разборчиво. Две фразы друг на друга не накладываются.
- Пауза, перемотка и скорость YouTube действуют и на голос. Громкость и mute YouTube —
  тоже.
- Если подготовка не успевает, видео встаёт на паузу с «Догружаю озвучку…» и продолжается
  само. Если в этот момент пользователь сам нажмёт «играть», не мешаем: недоготовленные
  фразы идут без голоса.
- Во время рекламы голоса нет, оригинал звучит нормально. После рекламы озвучка
  продолжается.
- «Озвучка ✓» → выключить: голос смолкает, громкость оригинала прежняя. Повторное включение
  на том же видео мгновенное: переводы и звук ещё в памяти.

### Как устроено

- **service worker**, сессия этапа 2:
  - переведённые фразы попадают в очередь синтеза. Синтезируем по одной: сервер
    однопоточный (`threaded=False`). Порядок — по времени от позиции воспроизведения, окно
    — 90 с вперёд. Синтез идёт параллельно с переводом: пока Ollama переводит батч N+1,
    Silero озвучивает батч N. Silero на CPU, за VRAM с Ollama не спорит;
  - подгонка длины (`src/dub/lib/fit.js`, чистые функции). Место фразы — от её начала до
    начала следующей; у последней — до её конца плюс 1,5 с. Синтезируем с `medium` и меряем
    длительность через `wavDuration`. Если не влезает больше чем на 10%, синтезируем заново
    с `fast` или `x-fast` — это естественнее, чем ускорять запись. Остаток превращается в
    `playbackRate` для вкладки. Произведение не больше `dubMaxSpeed`;
  - вкладке уходит `audio { id, data (base64), duration, rate }`. `ArrayBuffer` → base64
    кусками по 32 КБ через `String.fromCharCode`;
  - `evicted { ids }` от вкладки снимает с фраз отметку «озвучена»: если пользователь
    перемотает назад, синтезируем снова.
- **`src/dub/player.js`** (новый content script, перед `content.js`) — синхронизация:
  - звук фразы: base64 → `Blob` → `blob:` URL → `<audio>`. Если CSP не пустит, переходим на
    `data:` или Web Audio (риск 5);
  - пока видео играет, таймер раз в 100 мс: фраза, чьё начало пройдено меньше 0,3 с назад,
    запускается с `playbackRate = video.playbackRate × rate` и `preservesPitch = true`.
    Предыдущая ещё звучит → новая ждёт её конца. Отставание больше 3 с → ждущая фраза
    пропускается;
  - события `<video>`: `pause`/`play` → пауза и продолжение текущей фразы; `seeking` →
    оборвать фразу, на `seeked` — с позиции: внутри фразы, если от неё осталось больше
    половины, иначе со следующей, и `position` в service worker; `ratechange` → пересчитать
    `playbackRate`; `volumechange` → громкость голоса = `video.volume`, с учётом `muted`;
  - приглушение: `AudioContext` → `createMediaElementSource(video)` → `GainNode`. Gain равен
    `dubOriginalVolume`, пока озвучка включена, и 1 — когда выключена. `<video>` YouTube
    переиспользует между видео, а `createMediaElementSource` можно вызвать на элементе
    только один раз — узел храним в `WeakMap`. Если бросит, запасной вариант —
    `video.volume` с восстановлением (риск 4);
  - буферизация: позиция дошла до фразы без звука, а её ещё готовят → `video.pause()` и
    «Догружаю…». Продолжаем, когда готовы следующие ~15 с, и только если ставили на паузу
    сами;
  - реклама: класс `ad-showing` у `#movie_player` → фраз не запускаем, gain 1;
  - память: звук фраз хранится строкой base64, `blob:` URL создаётся на время звучания фразы
    и сразу отзывается. Звук дальше 60 с позади позиции и дальше 150 с впереди (остаётся
    после перемотки назад) выбрасываем и шлём `evicted`. Переводы храним все: они маленькие;
  - `ended`, смена видео, выключение → всё обрываем, gain 1.
- **content.js** — кнопка и состояния: «Озвучить», «Готовлю озвучку… N%», «Озвучка ✓»,
  «Догружаю…», «▶ Продолжить», «⚠ …». Субтитры теперь по настройке `dubSubtitles`.
- **Ошибки Silero** (`TTS_DOWN`) — на кнопке: «⚠ Silero не отвечает». Подсказка — как его
  запустить.

### Файлы

`src/dub/background.js`, `src/dub/player.js` (новый), `src/dub/content.js`,
`src/dub/lib/fit.js` (новый), `src/dub/lib/queue.js`, `manifest.json` (`player.js` в
`content_scripts` озвучки).

### Чек-лист

1. Ollama и Silero запущены. Английское видео на ~10 минут → «Озвучить» → «Готовлю
   озвучку… N%» → видео продолжается с русским голосом, оригинал тихо фоном.
2. Фразы начинаются вместе с английскими (±0,5 с), друг на друга не наезжают. Длинные
   звучат быстрее, но разборчиво.
3. Пауза и продолжение в YouTube → голос тоже. Скорость 1,5× → голос быстрее.
4. Перемотка назад и вперёд на минуту → голос с нового места. Далеко вперёд → «Догружаю…»,
   потом видео идёт само.
5. Ползунок громкости и mute YouTube действуют и на голос. Выключить озвучку → оригинал
   на прежней громкости, ползунок YouTube не сдвигался. Перезагрузить страницу → громкость
   YouTube прежняя.
6. Видео с рекламой → во время рекламы голоса нет, реклама звучит нормально. После неё

7. Перейти на другое видео → голос смолкает сразу, кнопка сброшена.
8. «■ Стоп» в popup → голос смолкает, на кнопке «▶ Продолжить».
9. Включить озвучку на 30-минутном видео, переключиться на другую вкладку и вернуться

10. Диспетчер задач Chrome (Shift+Esc): память вкладки за 20 минут не растёт неограниченно.
11. Остановить Silero во время просмотра → «⚠ Silero не отвечает». Запустить и нажать →
    продолжается.
12. Firefox: пункты 1–5. Chrome на Linux с systemd-Silero: пункты 1–3.

## Этап 5. Доработки (по желанию, выбираем после этапа 4)

- **Длительность в промпте**: «уложись в ~N секунд». Меньше ускорения речи.
- **Отдельная модель для озвучки**, если основная не успевает (риск 2).
- **Хоткей** `Alt+Shift+V`: озвучка на текущей вкладке.
- **Shorts и встроенные плееры.**
- **Видео без субтитров через ваш whisper-сервер.** Нужны таймкоды, а `POST /transcribe`
  отдаёт только текст — сервер придётся дорабатывать.
